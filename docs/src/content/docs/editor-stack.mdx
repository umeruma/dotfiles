Lazyvimを試している。急いでいるときはCursor or Zedを使う。

| Tool | Role | Config |
| --- | --- | --- |
| [LazyVim](https://www.lazyvim.org/) | Neovim ディストリビューション（エディタ） | `home/.config/nvim`（macOS → `~/.config/nvim` / Windows → `%LOCALAPPDATA%\nvim`） |
| [lazygit](https://github.com/jesseduffield/lazygit) | Git の TUI | `home/.config/lazygit`（Unix）/ `home-win/.config/lazygit`（Windows → `%LOCALAPPDATA%\lazygit`） |
| [herdr](https://herdr.dev/) | コーディングエージェント用のマルチプレクサ（Windows のみ。macOS は Rex） | `home-win/.config/herdr`（→ `%APPDATA%\herdr`） |
| [Crit](https://crit.md/) | AI エージェント向けのローカルレビューツール | なし（単一バイナリ） |
| [revdiff](https://revdiff.com/) | AI エージェント向けの TUI レビューツール（試用中） | `home/.config/revdiff`（テーマは cendre を自作。シンタックスは近い gruvbox） |
| [hunk](https://hunk.dev/) | エージェントの変更を読む diff ビューア（試用中）。`hunk diff --watch` を隣のペインに置き、`hunk-review` スキルで解説を書き込ませる | `home/.config/hunk/config.toml`（cendre hard） |

## Prerequisites

macOS は `mise run switch`（`nix/home-manager/tools/`）、Windows は `mise run install-apps`（winget）でインストールされる:

- `neovim`
- `herdr`（Windows のみ。公式 `install.ps1`、`mise run install-herdr` / `install-apps`）
- `lazygit`
- `git-delta`（lazygit の syntax-highlighted diff。macOS: Nix / Windows: `winget:dandavison.delta`。テーマは [cendre](https://cendretheme.com/) hard — `~/.config/delta/cendre.gitconfig` + bat `cendre` theme）
- `bat`（delta の `syntax-theme = cendre` 用。`mise run theme` で `bat cache --build`）
- `ripgrep`、`fd`（LazyVim の grep / ファイル検索に必須）
- `tree-sitter-cli`（macOS: Nix。Windows は LazyVim/mason が入れる。パーサービルド用に `winget:BrechtSanders.WinLibs.POSIX.UCRT`）
- `crit`（エージェントの変更をブラウザ UI で行コメントレビューする。`crit <file>` / `crit <url>` で起動）
- `revdiff`（diff やファイルに TUI で注釈を付け、終了時にエージェントへ返す）

crit は Web ページのレビュー（`dev-crit`）に使う。revdiff は Web ページを扱えない。Claude Code の `/crit` スキルは、プラグインではなく `crit install claude-code` で `~/.claude/skills/` に入れる。プラグインにはプランを作ったときに crit を開くフックが付いていて、revdiff のフックとぶつかるため。`crit.nix` の activation が、switch のたびに今の crit で入れ直す。

revdiff はプラグインで入れる（`/revdiff main` などで起動）。プランを作ったときに自動で開くのは、`revdiff-planning` のほう。プラグインの実体は `~/.claude/plugins` にあり、Claude Code が管理する。`revdiff.nix` の `my.claudePlugins` に書いておけば、switch のときに入っていなければ入る（このときはネットワークが要る）。`revdiff.nix` を消してもプラグインは残るので、`claude plugin uninstall` で消す。

どちらのプラグインも Rex を検出できず、そのままだとエラーになる。そこで `revdiff.nix` が、自作のランチャー（`home/.claude/revdiff/` の `launch-revdiff.sh` と `launch-plan-review.sh`）を各プラグインの `~/.claude/plugins/data/*/scripts/` にリンクしている。Rex の中では、エージェントのウィンドウの上にフロートペインで revdiff を開く（フロートできなければズーム）。閉じたらフォーカスをエージェントのペインに戻す。Rex の外では、同梱のランチャーに処理を渡す。

## Setup

```bash
mise run switch         # macOS（アプリとリンク）
# Windows: mise run install-apps && mise dotfiles apply -y
nvim --headless "+Lazy! sync" +qa   # プラグインの初回インストール
```

`nvim` の初回起動でも同じ同期が走るので、headless での実行は省略してもよい。

## How it is linked

`~/.config/nvim`（Windows では `%LOCALAPPDATA%\nvim`）は**ディレクトリごと**リンクしている。LazyVim が `lazy-lock.json` をリンク越しにリポジトリへ書き戻すため、プラグインのバージョンが git で追跡される。プラグイン本体は Unix では `~/.local/share/nvim`、Windows では `%LOCALAPPDATA%\nvim-data`、セッション状態はそれぞれ `~/.local/state/nvim` / nvim-data 配下に入るのでリポジトリは汚れない。

`%APPDATA%\herdr` はログ・ソケット・`session.json` が同じディレクトリに書かれるので、`config.toml` だけを**ファイル単位**でリンクしている（`~/.config/lazygit` と同じ扱い）。

## herdr config

設定なしでも動く。このリポジトリ（Windows）では次の点だけ変えている:

- `theme.name = "terminal"` — Windows Terminal のテーマ（cendre）にそのまま追従させる
- `experimental.reveal_hidden_cursor_for_cjk_ime` — Claude Code / Codex のように自前でカーソルを描く TUI で、IME の候補ウィンドウがカーソルを追従するようにする。`cjk_ime_agents` で対象を絞っているのは、全面適用すると Neovim のノーマルモードでカーソルが二重に見えるため
- `ui.host_cursor = "native"` — IME の候補ウィンドウの位置を正しくする。出力が多いとちらつくことがある（[Windows support](https://herdr.dev/docs/windows-beta/)）

コメント付きのデフォルト全文は `herdr --default-config`、設定の検証は `herdr config check`、起動中のサーバーへの反映は `herdr server reload-config`。

## Daily use

```bash
herdr / hr   # Windows のみ。セッションを起動 / attach（prefix は ctrl+b、ヘルプは prefix+?）
nvim / n     # LazyVim（リーダーキーは space）。`n +100 file.rs` もそのまま通る
lazygit / lg # Git TUI（Files で A = AI コミットメッセージ）
```

diff は [delta](https://github.com/dandavison/delta)（`git.diffRenderers`）+[cendre](https://cendretheme.com/) hard（`.gitconfig` が `~/.config/delta/cendre.gitconfig` を include。syntax は bat の `cendre` theme）。行番号クリックでエディタへジャンプ（hyperlinks）。`|` で renderer 切替。

`n` / `lg` は `~/.zshrc`（Windows は PowerShell プロファイル）の薄いシェル関数。`hr` は PowerShell プロファイルだけにある。

lazygit の `A` は **staged の diff だけ** を AI に渡す。macOS / Linux は `claude -p --model haiku`（`LAZYGIT_AI_CMD` で差し替え可）、Windows は `cursor-agent`（`composer-2.5-fast`）。生成中は下ステータスの `loadingText`（中央オーバーレイは非対応）。完了後は lazygit の保存メッセージ（`.git/LAZYGIT_PENDING_COMMIT`、Esc で閉じたときに復元されるもの）に書き込み、nvim 内（LazyVim の lazygit 統合）なら `$NVIM` の RPC ソケット経由で `c` を注入してプリフィル済みの commit パネルを開く。Enter は自分で押す。nvim 外ではポップアップで「c を押せ」と案内する。要: stage 済みであること。macOS / Linux は `claude` と `commit.template`（`~/.gitmessage`）、Windows は `cursor-agent login`（または `CURSOR_API_KEY`）。ヘルパー本体は macOS / Linux が `generate-commit-msg.sh`、Windows が `generate-commit-msg.ps1`（`mise.windows.toml` が `%LOCALAPPDATA%\lazygit` にリンク）。

LazyVim のプラグイン追加は `home/.config/nvim/lua/plugins/` に `.lua` を置くだけでよい（`example.lua` が雛形）。`lazy-lock.json` の差分はそのままコミットする。
