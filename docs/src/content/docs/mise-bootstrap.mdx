## Overview

基本的なマシンセットアップは [`mise bootstrap`](https://mise.jdx.dev/bootstrap.html) が担当。

curl インストーラー（`install`）は、mise が存在する前に必要なステップを担当する:

1. このリポジトリを `~/Codes/dotfiles` に clone（または pull）
2. macOS では Xcode Command Line Tools をインストール（`init/init-macos.sh`）
3. Linux では Homebrew をインストール（`linux/Brewfile` を使う `install-apps` 用）、macOS では Nix をインストール（`mise run switch` 用。Homebrew は nix-homebrew が入れる）
4. mise 自体をインストール（`curl https://mise.run | sh`）
5. `mise trust` + `mise bootstrap --yes --update` を実行

宣言的なマシン状態は以下に置く:

- [`.miserc.toml`](https://github.com/umeruma/dotfiles/blob/main/.miserc.toml) — early-init（`auto_env = true` で OS 別設定を読み込む）
- [`mise.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.toml) — 共通の bootstrap user/task と mise タスク
- [`mise.linux.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.linux.toml) / [`mise.macos.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.macos.toml) / [`mise.windows.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.windows.toml) — OS ごとの設定
- [`flake.nix`](https://github.com/umeruma/dotfiles/blob/main/flake.nix) — macOS のパッケージ・アプリ・リンク（[Nix (macOS)](/nix)）

## macOS

macOS では、パッケージもアプリもリンクも `mise bootstrap` では入れず、Nix に任せる。流れは次のとおり:

1. `install` が Xcode Command Line Tools と Nix（Determinate インストーラー）、mise を入れる
2. `mise bootstrap` が macOS defaults とログインシェルを適用する
3. `post-defaults` フックが `mise run switch` を実行し、nix-darwin・home-manager・Homebrew を反映する（`sudo` のパスワードを聞かれる）

2回目以降は `mise run switch` だけでよい。

## What `mise bootstrap` does here

| Phase | Config | This repo |
| --- | --- | --- |
| packages | `mise.linux.toml` の `[bootstrap.packages]` | Linux: `apt:build-essential`、`apt:zsh`（Debian 系）／`pacman:base-devel`、`pacman:zsh`（Arch 系）。使えない manager の行は mise が skip する。macOS は Nix が入れる |
| dotfiles | `mise.linux.toml` / `mise.windows.toml` の `[dotfiles]` | `home/`・`home-win/` の宣言的 symlink allowlist（実行時書き込みのある dir はファイル単位）。macOS は `[dotfiles]` を持たず、home-manager がリンクする（`mise run switch`） |
| macOS defaults | `mise.macos.toml` の `[bootstrap.macos.*]` / `[bootstrap.macos.defaults]` | Dock・Finder・キーボードなどスカラー値の設定（配列 / PlistBuddy は未移行） |
| hooks | `mise.macos.toml` の `[bootstrap.hooks.post-defaults]` | Dock・Finder を再起動し、`mise run switch` を実行する |
| user | `[bootstrap.user]` | `login_shell = "/bin/zsh"`（`install` 内の旧 `chsh` ブロックを置き換え） |

再実行しても安全: 宣言的なフェーズは収束する。

マシンを変更せずにプレビュー:

```
dot && mise bootstrap --dry-run --yes
```

不足しているものの確認:

```
dot && mise bootstrap status --missing
```

macOS defaults の差分（macOS のみ）:

```
dot && mise bootstrap macos defaults status
dot && mise bootstrap macos defaults apply --dry-run --yes
```

## What stays outside bootstrap (for now)

以下は意図的に bootstrap の外で管理:

| Piece | Why |
| --- | --- |
| `install-win` + `win/bootstrap.winget` | PowerShell 7 / Git / mise 自体を入れるステップ。mise が存在する前なので bootstrap では扱えない |
| `linux/Brewfile`（`mise run install-apps` 経由） | 意図的: `brew bundle add` / `brew bundle cleanup` の追加・追跡ワークフローが便利なため。bootstrap にはデプロイに必須のパッケージだけ残す |
| Windows GUI アプリ（`mise.windows.toml` の `[bootstrap.packages]`） | `[bootstrap.packages]` に**宣言はする**が、`mise run install-apps`（= `mise bootstrap packages apply`）でのみ適用する opt-in 扱い。Brewfile と対称 |
| Xcode CLT | 対話的な `xcode-select --install` |

## Gradual migration ideas

experimental な bootstrap に慣れてきたら:

1. **Shell activation** — `.zshrc` に書いている `eval "$(mise activate zsh)"` を mise 管理にしたければ、オプションの `[bootstrap.mise_shell_activate]` を使う

（完了済み: macOS defaults → `[bootstrap.macos.defaults]`、stow → `[dotfiles]`、PSDotFiles → `[dotfiles]`、`win/apps.winget` → `[bootstrap.packages]`、macOS の Brewfile とリンク → Nix。予定なし: `linux/Brewfile` → `[bootstrap.packages]` — `brew bundle` ワークフローは欠点ではなく機能なので）

`mise bootstrap` はまだ experimental 扱いのため、このリポジトリの `mise.toml` では `settings.experimental = true` を設定している。
