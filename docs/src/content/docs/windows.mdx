## Overview

Windows のセットアップも macOS / Linux と同じ mise の宣言的な仕組みに載っている:

- **mise `[dotfiles]`** — [`mise.windows.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.windows.toml) の allowlist で [`home-win/`](https://github.com/umeruma/dotfiles/tree/main/home-win) と [`home/`](https://github.com/umeruma/dotfiles/tree/main/home) を `$HOME` にリンクする
- **mise `[bootstrap.packages]`** — `winget:<id>` でアプリをインストールする
- **[WinGet Configuration](https://learn.microsoft.com/en-us/windows/package-manager/configuration/)** — [`win/bootstrap.winget`](https://github.com/umeruma/dotfiles/blob/main/win/bootstrap.winget) のみ。mise 自体を入れる鶏卵ステップで、mise が無い状態で走る唯一のもの

`[dotfiles]` の分割は以下のとおり:

| ファイル | 適用 OS |
| --- | --- |
| `mise.dotfiles.toml` | 全 OS 共通（`~/.agents`、Claude/Copilot の設定など） |
| `mise.unix.toml` | macOS + Linux |
| `mise.windows.toml` | Windows（`~/.gitconfig` など3件は `home-win/` の内容で上書き） |
| `mise.macos.toml` | macOS のみ |

## Prerequisites

新規またはリセット直後の Windows では、まず Microsoft Store から **App Installer**（winget）を入れる。自分で用意する必要があるのは winget だけで、**Git**・**PowerShell 7**・**mise** はすべてスクリプトが winget 経由で自動インストールする。

install-win 実行時に winget がない場合、スクリプトが App Installer の Store ページを開いて案内を表示して停止する。App Installer を入れてからコマンドを再実行する。

## install-win

このリポジトリは `~/Codes/dotfiles` に配置する。

実行前にスクリプトを確認する:  
[https://dot.umeru.ma/install-win](https://dot.umeru.ma/install-win)

install-win の前に **開発者モード** を有効にする（symlink 作成に必要）。

設定ページを直接開くには:

```powershell
Start-Process "ms-settings:developers"
```

**PowerShell** で実行（ブートストラップは Windows PowerShell 5.1 でも OK。途中で PowerShell 7 で再起動する）:

```powershell
irm https://dot.umeru.ma/install-win | iex
```

やっていること:

1. 必要なら PowerShell 7 をインストール
2. リポジトリを `~/Codes/dotfiles` に clone（既存なら最新を pull）
3. [`win/bootstrap.winget`](https://github.com/umeruma/dotfiles/blob/main/win/bootstrap.winget) で `winget configure` を実行（PowerShell 7、Git、mise）
4. `mise run deploy` で `[dotfiles]` を適用

Windows PowerShell 5.1 から始めた場合、スクリプトは PowerShell 7 で自分自身を再起動して残りを実行する。完了後もターミナルは開いたままで、最後に GUI アプリ用の `mise run install-apps` を案内するバナーが表示される。

## Deploy dotfiles

**PowerShell 7** でリポジトリのルートから:

```
cd $env:USERPROFILE\Codes\dotfiles
mise run deploy
```

macOS / Linux と同じ `mise dotfiles apply -y` を実行する。親ディレクトリは mise が自動で作るので、事前準備は要らない。

リポジトリを最新にする（`git pull --no-ff origin main`）:

```
mise run update
```

宣言の一覧と状態:

```
mise dotfiles status
```

symlink を削除するには（[`script/clean-windows.ps1`](https://github.com/umeruma/dotfiles/blob/main/script/clean-windows.ps1) がリポジトリを指すリンク/ジャンクションだけを掃く）:

```
mise run clean
```

## Install applications

GUI などのアプリは [`mise.windows.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.windows.toml) の `[bootstrap.packages]` に `winget:<id>` 形式で列挙している:

```
mise run install-apps
```

これは `mise bootstrap packages apply -y` のあと、[Cursor CLI](https://cursor.com/docs/cli/overview) の公式 Windows 手順（`irm 'https://cursor.com/install?win32=true' | iex`）を冪等に実行する（[`script/install-apps-windows.ps1`](https://github.com/umeruma/dotfiles/blob/main/script/install-apps-windows.ps1)）。macOS の Brewfile と同じく **opt-in**（`mise bootstrap` 本体からは切り離してある）。CLI 単体だけ入れる場合:

```
mise run install-cursor-cli
```

追加・状態確認・削除:

```
mise bootstrap packages use winget:Publisher.App   # 追加してインストール
mise bootstrap packages status                     # 未インストールの確認
mise bootstrap packages prune                      # 宣言から消したものを削除
```

winget を `[bootstrap.packages]` のマネージャーとして扱えるのは **mise 2026.9.3** 以降。それ以前は `win/apps.winget`（winget DSC 設定）を使っていた。

LazyVim（`home/.config/nvim`）は `%LOCALAPPDATA%\nvim` に symlink され、`winget:Neovim.Neovim` / ripgrep / fd / lazygit / WinLibs（treesitter 用 C コンパイラ）は `install-apps` で入る。初回は `nvim` を起動して Lazy sync（または `nvim --headless "+Lazy! sync" +qa`）。ショートカットは PowerShell プロファイルの `nv` / `lg`（`nv` は組み込みエイリアス `New-Variable` を外してから定義）。

## Terminal theme (cendre)

macOS の Ghostty / Terminal.app と同じ [cendre](https://github.com/Aejkatappaja/cendre)（hard）を Windows Terminal に入れる（opt-in）:

```
mise run theme
```

`extras/windows-terminal/cendre.json` を `%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\cendre\` にコピーする（Preview が入っていればそちらの Fragments にも）。Windows Terminal を再起動し、Appearance → Color scheme で `cendre` を選ぶ。

## Kanata (keyboard remapper)

macOS の Karabiner と揃えた IME 切り替えの全体像は [IME Switching](/setup-hard/ime-switching/) を参照。

[Kanata](https://github.com/jtroo/kanata) は `mise run install-apps`（`winget:jtroo.kanata_gui`）でインストールする。ポータブル zip パッケージで、winget が GUI バイナリを `%LOCALAPPDATA%\Microsoft\WinGet\Links` 配下のコマンドエイリアス `kanata_windows_gui_winIOv2_x64` として登録するため、手動ダウンロードは不要。

設定は [`home-win/Documents/kanata/kanata.kbd`](https://github.com/umeruma/dotfiles/blob/main/home-win/Documents/kanata/kanata.kbd) にあり、`[dotfiles]` が `~\Documents\kanata\kanata.kbd` に symlink する。HHKB（US 配列）+ **2 つの入力方式**（English (US) IME + 日本語 Microsoft IME）を前提にしている:

- **左 Win タップ** → English (US) IME に切り替え
- **右 Win タップ** → 日本語 IME に切り替えてかなを ON
- 長押しや他キーとの組み合わせ → Win キーは通常どおり動作

### Input language hot keys (required)

Kanata は特定の IME を直接選択できない — Windows が公開しているのは循環切り替えのショートカット（`Win+Space` / `Alt+Shift`）だけ。そこで設定では言語ごとの切り替えホットキーを送信しているため、一度だけ割り当てが必要:

```powershell
Start-Process "ms-settings:typing"
```

**キーボードの詳細設定 → 入力言語のホットキー**（クラシックな *テキスト サービスと入力言語 → キーの詳細設定* ダイアログが開く）で以下を設定する:

| Action | Key sequence |
|---|---|
| **日本語 - Microsoft IME** へ切り替え | `左Alt+Shift+1` |
| **英語 (米国)** へ切り替え | `左Alt+Shift+2` |

![言語ごとの切り替えホットキーを割り当てたキーの詳細設定ダイアログ](https://i.gyazo.com/bfcd161911640184eb11aaee778d8b52.png)

これらは [`kanata.kbd`](https://github.com/umeruma/dotfiles/blob/main/home-win/Documents/kanata/kanata.kbd) の `A-S-1` / `A-S-2` と一致させる必要がある。アプリのショートカットと衝突する場合は、両方で別の数字（例: `Ctrl+Shift+1/2` → `C-S-1` / `C-S-2`）に変える。

Windows 11 24H2 では旧来の `rundll32 ... input.dll ... {HOTKEYS}` 呼び出しが効かないことが多いので、上記の `ms-settings:typing` 経由を使う。

### Autostart

ログイン時に kanata を自動起動するには、（`install-apps` と `deploy` の後に）一度だけスタートアップのショートカットを作成する:

```
mise run setup-kanata
```

これはスタートアップフォルダに `Kanata.lnk` を作成し、winget でインストールした exe を `--cfg ~\Documents\kanata\kanata.kbd` 付きで指す（最小化してシステムトレイに常駐）。ログアウトせずすぐ起動するには:

```powershell
Start-Process "$([Environment]::GetFolderPath('Startup'))\Kanata.lnk"
```

`winIOv2` バリアントは Windows の LLHOOK + SendInput を使うため、ドライバも管理者権限も不要。ただし管理者権限（UAC）で動くウィンドウには効かない。そこでもリマップしたい場合は、スタートアップショートカットの代わりにタスクスケジューラでログオン時に最上位特権で起動する。

## PowerShell profile and mise

[`home-win/Documents/PowerShell/Microsoft.PowerShell_profile.ps1`](https://github.com/umeruma/dotfiles/blob/main/home-win/Documents/PowerShell/Microsoft.PowerShell_profile.ps1) で以下を設定している:

- `$env:DOTFILES`
- `dot` でリポジトリに移動
- シェル起動時に `mise activate pwsh`

**PowerShell 7**（`pwsh`）を使うこと。Windows PowerShell 5.1 での mise activation はサポートされない。[mise PowerShell discussion](https://github.com/jdx/mise/discussions/6733) を参照。

## Claude Code plugins

プラグインの実体は `~/.claude/plugins` に入る。中身は marketplace の git clone（`marketplaces/<name>/`）とバージョン付きキャッシュ（`cache/<marketplace>/<plugin>/<version>/`）なので、このディレクトリは追跡しない。追跡するのは宣言だけ。

[`home-win/.claude/settings.json`](https://github.com/umeruma/dotfiles/blob/main/home-win/.claude/settings.json) に marketplace を `extraKnownMarketplaces`、プラグインを `enabledPlugins` で列挙する。`~/.claude` は Claude Code が書き込む実ディレクトリなので、ディレクトリごとではなくファイル単位で symlink する（`[dotfiles]` に `~/.claude/settings.json` を個別に宣言している）。

新しいマシンでは `mise run deploy` と再起動だけでは**途中までしか進まない**。marketplace の登録と `cache/` への先読みまでは走るが、git リポジトリ由来のプラグインは `enabledPlugins` だけでは install が完了しない。マシンごとに一度だけシェルコマンドで仕上げる（`/plugin` スラッシュコマンドは対話ターミナルが必要なので使わない）:

```
claude plugin install <plugin>@<marketplace>
claude plugin list
```

`plugin list` が `Status: enabled` を返せば完了。起動中のセッションに反映するには `/reload-plugins`。

Claude Code は symlink 越しに書き戻すので、アプリ側で変更した設定（テーマ、自動追加される marketplace など）はリポジトリの差分として現れる。プラグインを増やすときは `home-win/.claude/settings.json` と `home/.claude/settings.json` の両方に追記する（`home/` と `home-win/` を分けている方針どおり、意図的に二重管理）。

### hooks を使うプラグインは node が必要

SessionStart などの hook を持つプラグインは `node` を実行する。GUI アプリは**永続ユーザー PATH しか継承しない**ため、`mise activate pwsh` でシェル起動時にだけ通している状態では hook が毎回失敗する。スキルは使えるのに hook だけ効かない、という分かりにくい壊れ方をする。

node のバージョンは [`home-win/.config/mise/config.toml`](https://github.com/umeruma/dotfiles/blob/main/home-win/.config/mise/config.toml) で宣言済みで、deploy が `~/.config/mise/config.toml` に symlink する。プロジェクトの `mise.toml` に `[tools]` を書くのでは届かない — それはそのディレクトリの中でしか解決しないため。

残る手作業は shims を永続 PATH に入れること。マシンごとに一度だけ:

```powershell
[Environment]::SetEnvironmentVariable('Path', "$env:LOCALAPPDATA\mise\shims;" + [Environment]::GetEnvironmentVariable('Path','User'), 'User')
```

設定後は GUI アプリを再起動する。`~/.claude/.ponytail-active` のようなプラグイン側の状態ファイルができていれば hook が動いている。

## Developer Mode (symlinks)

**開発者モード** を有効にする:

**設定 → システム → 開発者向け → 開発者モード**

またはデプロイ用シェルを管理者として実行する。

これは必須。開発者モードがないと mise は symlink を作れず、**エラーにならず copy にフォールバックする**。見た目は成功するが、`$HOME` 側で編集した内容がリポジトリに戻らず `git status` にも出ない。`mise run clean` は開発者モードが無効なら警告を出す。

`$PROFILE` がすでに存在する場合は、最初のデプロイ前にバックアップする。適用内容の事前確認:

```
mise dotfiles status
```

## `home/` vs `home-win/`

| Directory   | Used on        | Tool        |
|------------|----------------|-------------|
| `home/`    | macOS, Linux（一部は Windows でも） | mise `[dotfiles]` |
| `home-win/`| Windows        | mise `[dotfiles]` |

Windows 専用のファイルは `home-win/` に置き、mac 専用ツール（Karabiner、Ghostty など）が Windows にデプロイされないようにする。
