## install (macOS / Linux)

実行前にスクリプトの中身を確認します: 

> [https://dot.umeru.ma/install](https://dot.umeru.ma/install)

Terminal.app を開いて実行:

```
bash -c "$(curl -fsSL https://dot.umeru.ma/install)"
```

bash と curl のオプションのメモ:

bash:
- `-c`: 渡した文字列を bash コマンドとして実行する（例: `bash -c "echo hello"` は `hello` を出力）

curl:
- `-f` (`--fail`): HTTP エラー（4xx/5xx）のときはエラーページを出力せず、非ゼロで終了する
- `-s` (`--silent`): 進捗バーやエラーメッセージを表示しない
- `-S` (`--show-error`): `-s` と組み合わせると、エラーメッセージだけは表示する
- `-L` (`--location`): リダイレクト先までたどってダウンロードする

インストール実行後、dotfiles リポジトリは `~/Codes/dotfiles` にcloneされます。すでに存在する場合はHEADをpullしてインストール処理を実行します。

インストーラーは [`mise bootstrap`](https://mise.jdx.dev/bootstrap.html) を実行して、定義されているmacOS用のdefaultsの適用を行ったのち、`$HOME`へのdotfilesのデプロイを行います。詳細は、 [mise bootstrap](/mise-bootstrap)。

## jump to dotfiles (on all platform)

.zshenv と .zshrc にこのような定義があり、
```
# on .zshenv
export DOTFILES="$HOME/Codes/dotfiles"

# on .zshrc
dot() { cd "$DOTFILES" || return; (( $# )) || return 0; mise run "$@"; }
```

ターミナルで`dot`を実行することで、dotfiles ディレクトリにすぐ移動できます。`dot switch` のようにタスク名を付けると、移動したうえで `mise run <task>` を実行します。

## Link dotfiles

dotfiles をホームディレクトリにリンクするには:

```
dot switch                      # macOS
dot && mise dotfiles apply -y   # Linux / Windows
```

### How it works

macOS は home-manager、Linux と Windows は mise の `[dotfiles]` でリンクします。どちらもリポジトリへ直接リンクするので、ファイルを編集すればその場で反映されます。

- macOS: [`nix/home-manager/dotfiles.nix`](https://github.com/umeruma/dotfiles/blob/main/nix/home-manager/dotfiles.nix)（ツール固有のものは `nix/home-manager/tools/<tool>.nix`）
- Linux: [`mise.linux.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.linux.toml)
- Windows: [`mise.windows.toml`](https://github.com/umeruma/dotfiles/blob/main/mise.windows.toml)

`~/.agents` や `~/.claude/*` など全 OS で同じファイルは、3か所に1回ずつ書いています。Mac は `[dotfiles]` を1件も読みません。読むと `mise bootstrap` が Nix と同じ場所にリンクを張り、home-manager とぶつかるためです。

macOS では `~/.config` をまるごと `home/.config` にリンクしています（[babarot/dotfiles](https://github.com/babarot/dotfiles) と同じ方式）。ツールが書き込む状態ファイルや認証情報は [`home/.config/.gitignore`](https://github.com/umeruma/dotfiles/blob/main/home/.config/.gitignore) で除外します。新しいツールのファイルは untracked として出てくるので、そのつど追跡するか除外するかを決めます。

Linux（Omarchy）は `~/.config` を Omarchy が管理しているので、まるごとリンクはしません。実行時に書き込みのあるディレクトリ（例: `~/.config/lazygit`、`~/.config/herdr`）は**ファイル単位**でリンクします。

`mise dotfiles apply` は、宣言から消したエントリのリンクを残します。Linux と Windows でエントリを消したら、`mise run clean` でリポジトリへのリンクを全部外してから、`mise dotfiles apply -y` で張り直します。macOS では switch が古いリンクを自動で消します。

よく使うコマンド:

```
mise run switch        # nix/ の宣言どおりにアプリとリンクを反映（macOS）
mise dotfiles status   # 各設定の applied / differs / missing を表示（Linux / Windows）
dottrack <path>        # 既存ファイルのリポジトリ管理の開始

# cask を足すときは nix/home-manager/tools/ に my.casks = [ "<name>" ]; を書いて git add → switch
```

## macOS defaults

macOS の設定と差分を確認するには:

```
dot && mise bootstrap macos defaults status
```

詳細: [mise bootstrap](/mise-bootstrap)

## Terminal theme (cendre)

Ghostty（macOS）のテーマは設定ファイル（`home/.config/ghostty`）で適用される。`theme = cendre`。Terminal.app / Windows Terminal は opt-in で、明示的にコマンドを実行する:

```
dot theme
```

- macOS: [cendre](https://github.com/Aejkatappaja/cendre) の `extras/macos-terminal/cendre.terminal` を開いてプロファイルを取り込む（切り替えは Terminal.app の設定で）
- Windows: Fragments にスキームを置き、`settings.json` の `profiles.defaults.colorScheme` を `cendre` にパッチ（Terminal 再起動で反映）
